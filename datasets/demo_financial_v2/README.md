# FinAgent 完整金融档案与订阅案例集 v2

本版按“用户的金融经济信息”组织数据，入口是 **用户金融总览.csv**，每位用户一行。它连接名下银行账户、借记卡与信用卡、活期和定期、基金、房车、贷款、信用卡账单、保险、订阅合同与现金/负债流水。

观察期仍为 **2025-09-25至2026-09-24，共365天**；所有余额、状态和“下次扣款”均以 **2026-09-24** 为截至日，不能按打开文件的当天解释。首尾两个自然月为部分月份。

主案例全部是**合成数据**，不是任何真人的全量金融档案。银行、产品、保险和订阅服务均为虚构；利率、净值、费用、最低还款规则与使用记录都是明确的演示假设。真实公开零售参考单独保留，不混入案例银行流水。

## 资产、存款、额度和负债怎样区分

本版采用以下口径，避免出现“看似完整，实际重复计钱”的问题：

```text
全部银行存款 = 活期账面余额 + 尚未支取的定期本金
总资产 = 全部银行存款 + 基金期末市值 + 声明的房车估值
总负债 = 贷款剩余本金及已计未付利息 + 信用卡当前欠款
净资产 = 总资产 - 总负债
```

- 活期“账面余额”与“可用余额”分开：停用账户的账面余额仍是声明资产，但可用金额为0。单张借记卡被冻结，不表示所属账户的银行转账余额一定冻结；冻结卡本身的支付可用金额为0。
- **借记卡不另存一份钱**。多张借记卡若关联同一个账户，只计账户余额一次。信用卡关联负债账户，不伪装成有存款的账户。
- **信用卡额度不是资产**，剩余额度也不是活期存款。欠款分已出账与未出账；最低还款额只是虚构合同的10%/最低10元规则，不是银行通用规则。本案例采用全额已出账还款，未把未出账消费提前全部还掉。
- 定期本金从活期转入时，活期减少、定期增加；到期/提前支取时反向移动。因此不能把“资金仍留在活期”和“同一笔定期本金”同时计入资产。实付利息才进入现金收入；**未付应计利息仅单列参考，不计入总资产或可用存款**。
- 基金投资使用份额×虚构净值计算市值；后续申购按照当日虚构净值换算份额。投入本金不算消费，未实现收益也不伪造为银行已到账收入。基金不能与同一笔已经支付出去的活期余额重复计算。
- 房车属于非现金资产，使用者声明的估值不表示可以按此价格立即出售。本例没有房屋折旧、交易税费、其他家庭成员全部财产或法定养老金权益的估值模型。
- 保险是保障型案例，现金退保价值设为0；**100万元保额不是100万元存款或资产**。年度保费在现金消费中有对应记录。
- “贷款剩余本金及已计利息”不含未来尚未产生的所有利息。“下期贷款本金及利息”是未来付款计划，不能同时计入当前已形成负债两次。

何川的小店经营案例可能出现负净资产，这是设计的经营负债案例；可见账户现金非负不等于净资产必须为正。经营回款是毛回款，不等于工资、利润或全国统计中的经营净收入。

## 订阅和自动续费的重点案例

每份订阅都有明确的 `subscription_id`、`mandate_id`、扣款卡和支付方式。借记卡实际扣款落在现金流水；信用卡实际消费落在负债事件，之后还款才减少银行余额。这两类都可以演示“订阅消费”，但不能把刷卡和还款重复算成两次消费。

| 用户/场景 | 可以演示什么 |
|---|---|
| 林晓：云笺存储年付 | 2025-09-27曾扣198元，下次2026-09-27；截至9月24日属于未来计划，不能说已经扣款 |
| 陈予：协作办公 | 2026年6月由月付25元改为年付198元；旧月付历史保留、后续月扣停止，服务期间也随周期改变 |
| 许知夏：学习题库 | 2026-08-10开始试用，8月17日转为29元月付，首扣和后续扣款有记录 |
| 许澜：求职工具 | 9月20日开始免费试用，9月27日拟转49元月付；尚无成功扣费，可用于试用到期提醒 |
| 程雨：两家影音 | 同类服务同时订阅，标记可能重叠；用户需判断是否保留，不能自动取消 |
| 程雨：知识阅读 | 合成用户声明的最近使用日为5月10日，之后仍在付费；适合核对低使用订阅，不代表系统真的采集了设备行为 |
| 程雨：剪辑工具 | 9月20日关闭续费，权益到10月3日才结束；“关闭续费”不等于立刻失去权益或自动退款 |
| 苏禾：轻听音乐 | 5月申请取消，权益到6月11日，之后没有新增扣费；历史扣款不删除 |
| 沈悦：轻听音乐 | 7月开始暂停；暂停和已取消是不同状态 |
| 宋安：星幕影音 | 9月价格由19元调整到25元；历史账单仍用19元，不把旧记录全部重写为新价格 |
| 陆遥：出行工具箱 | 31日为月扣锚点，短月自动取月末；不是固定加30天 |
| 周宁：星幕影音 | 9月23日尝试续费时卡已冻结，失败原因CARD_FROZEN，没有成功扣款流水 |
| 叶舒：家庭云备份 | 绑定卡8月到期，9月尝试失败；原因CARD_EXPIRED，不能误报成余额不足 |
| 吴桐：配送工具年包 | 9月24日23:50尝试扣298元，来源账户此前因应急账单仅剩80元；失败且没有产生负余额或成功消费 |
| 顾嘉：家庭云空间 | 季付60元，展示非月付周期和未来一年合同成本折算 |

`next_billing_date` 是合同计划；`subscription_billing_events.status=paid` 才是观察期内成功扣款。失败尝试在扣费事件表保留，但现金流水和信用卡负债里没有对应成功消费。

失败的订阅费用属于待核对的服务付款，不自动登记为银行贷款或信用卡欠款；本案例没有推定服务商是否另行形成应付款债权。

`auto_renew_enabled=false` 的合同不再列下一次自动扣费。已支付的服务权益仍可能继续到 `access_end_date`。暂停、已取消、试用、逾期未付和仍正常使用分别存储。

`next_payment_risk` 结合截至日的绑定卡状态与余额提示风险；当前余额不代表未来余额。“近期扣款风险”不能当作未来必然扣费失败的结论。`annualized_contract_cost_minor` 是按当前合同价格和周期折算的年度费用，不是未来365天精确扣款日历，也不是过去一年实付金额。

## 对账和年度经济信息

现金流水、负债流水和资产持仓分账保存，然后统一做资产负债与现金流核对：

```text
期末净资产
= 期初净资产
  + 已入账收入
  - 现金消费净额
  - 信用卡消费（含信用卡订阅）
  - 当期贷款利息与模拟逾期费用
  - 外部转账转出
  + 基金未实现损益
```

本人账户互转、定期本金调拨、投资申购本金和偿还债务本金不重复算成消费。贷款利息是费用；本金还款是现金流和负债的同时减少。信用卡还款中可能包含观察期前承接的消费，因此不能简单用“年度还款额”冒充“年度消费”。

周宁2026-08-10至14日的工资账户故意缺流水、缺覆盖。对应月完整经济消费总额留空，年度总览也标出历史缺口。该用户的银行余额与净资产是**可见合成账本的声明值**，不能解释为完整真实账户的精确余额。失业或季节性零收入月在其他用户中属于已覆盖的真实零入账，不默认当作缺失。

独立验证脚本重读最终CSV，检查逐笔现金和负债、基金份额与净值、存款利息、信用卡账单、订阅合同与扣费、月度快照和20人的年度净资产变动桥接。最后结果见 `quality_report.json`。

## 文件格式与关联方法

全部CSV使用UTF-8 BOM，支持Excel/WPS中文显示；金额以整数分字段为权威值，中文总览的“_元”字段保留两位小数。编号不是账号，卡尾号不含完整卡号、CVV、密码或有效支付凭据。

- 用户用 `owner_id` 关联；中文总览使用“用户ID”。
- 借记卡用 `cards.account_id` 关联存款账户；信用卡用 `cards.liability_id` 关联负债，`repayment_account_id` 是还款资金账户。
- 订阅用 `payment_card_id` 关联卡，用 `mandate_id` 关联扣款授权。信用卡订阅的 `payment_account_id` 为空，不能自行填成另一张借记卡。
- 扣费事件只会关联一个成功记录：`cash_transaction_id` 或 `liability_event_id` 二选一。失败事件两者都为空。
- 贷款/信用卡还款在现金表与负债表用 `cash_transaction_id`/`business_id` 关联。
- 存款、基金、保险在现金表用 `financial_product_id` 关联各自产品明细。
- 信用卡滚动账单是时点快照，含历史结转，**不能把每月statement_balance相加当总负债**。当前总负债以逐笔负债账为准。

## 生成、校验与当前接入边界

本版保留v1文件，另存新目录，未修改原运行数据库、seed、业务接口或前端。银行/卡/订阅等新增字段与贷款、信用卡、存款、理财类型需要专门的导入与业务适配，不能直接宣称当前FinAgent已经能执行这些金融业务。订阅取消等演示问题描述数据所支持的场景，**尚不是已实现的真实操作能力**。

从项目根目录重新生成（需要此前v1的typed JSON输入和Codex内置表格依赖）：

```powershell
python scripts/build_financial_dataset.py
node scripts/export_demo_dataset.mjs --financial
python scripts/validate_financial_dataset.py
```

仅校验当前交付的CSV，只需最后一条命令和Python标准库，不需要模型密钥、Tavily或银行连接。年度卡/资产/合同模型的合成逻辑在 `scripts/build_financial_dataset.py`，其SHA-256在manifest中保留。

参考的真实公开资料仍见sources.csv：国家统计局汇总收支、Chen (2015) UCI Online Retail（CC BY 4.0，[DOI](https://doi.org/10.24432/C5BW33)）、IBM AMLSim公开方法说明及CTU历史银行数据目录。**公开参考没有提供这里20名用户的真实资料，也没有提供这里的真实价格或金融报价。** 本版没有新增付费搜索或模型调用，也没有使用此前提供的API密钥。
