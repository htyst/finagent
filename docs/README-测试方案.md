# FinAgent 测试方案 · 交付说明

这是一套**可执行的**测试方案，用来直观感受 FinAgent 整个项目的功能，并给后续优化留下抓手。
不修改任何业务代码，只新增测试资产。

## 二、这个项目是什么，测什么

FinAgent 是**基于合成数据的模拟银行智能助手**：React 工作台 + FastAPI 后端 + SQLite 账本 + DeepSeek 受限工具调用。

三条架构约束决定了整套测试策略：

1. **模型不能决定身份、算钱、直接提交** —— 所以模型相关测试只验"参数与预期一致"，不验"模型很聪明"。
2. **写业务必须页面按钮确认** —— 所以所有端到端写测试必须走确认接口，不能走对话。
3. **业务在单个事务内完成**（条件重算 + 快照校验 + 扣款 + 回执 + 审计） —— 所以并发与故障注入是重点，不是可选项。

### 业务数字的"标准答案"（已在真实库实测复核）

| 口径 | 手算过程 | 期望值 |
| --- | --- | --- |
| 本月餐饮净消费 | 1000.00 + 250.00 − 50.00 | **1200.00 元** |
| 上月同期餐饮净消费 | 900.00 − 100.00 | **800.00 元** |
| 环比增长 | 1200/800 − 1 | **+50.0%** |
| 本月购物净消费 | 88.00 + 11.00（待入账 77.00 不计） | **99.00 元** |
| 本月交通 / 未分类 | 24.00 / 32.00 | **24.00 / 32.00 元** |
| 账本恒等式 | 余额 = 期初 + 已入账贷记 − 已入账借记 | **6/6 账户差额为 0** |

```powershell

## 三、四层测试策略

| 层 | 内容 | 规模 | 成本 | 用途 |
| --- | --- | --- | --- | --- |
| T1 | 领域单元（金额、统计、条件、时钟） | 毫秒级 | 零 | 最快定位 |
| T2 | **集成测试**（FastAPI TestClient + 临时库） | **113 项** | 零，约 25–40 秒 | 回归主力 |
| T3 | 模型评估（mock / live，40 条样例） | 40 条 | live 花钱 | 能力评估，**不是回归** |
| T4 | 页面验收（Edge 真浏览器 + 真实库） | 4 组 | 约 20–30 分钟 | "用户真的能用" |

**永远不做的**：T3 不进默认检查（有随机性、要花钱）；T2 全绿不代表 T4 能过（历史上出现过前端构建通过但页面流程失败）。

### 判定纪律（来自项目自己的 `TEST_MATRIX.md`）

- 断言**持久化状态**，不以页面成功文案为准。
- 期望值用**手算**，不用被测函数自己算出的值当期望。
- 浏览器流程必须**从 UI 发起**，再回数据库验证。
- 每次测试用**独立临时数据库**。

## 四、三种运行档位

| 档位 | 做什么 | 实测耗时 |
| --- | --- | --- |
| `-Tier quick` | 领域规则 + 会话隔离 + 手算统计 + 限额（5 项） | **7 秒** |
| `-Tier standard` | 全部 113 项后端 + 前端类型检查 + 生产构建 | **27–43 秒** |
| `-Tier full` | standard + 受控响应回归 + M3–M6 浏览器验收 + 启动集成 | 20–30 分钟 |

```powershell
.\scripts\testplan.ps1 -Tier standard -NoOpen                       # 不自动打开报告
.\scripts\testplan.ps1 -Tier standard -OutDir 'D:\tmp\我的报告'      # 指定输出目录
.\scripts\testplan.ps1 -Tier full -Scope Backend                    # 只跑后端
```

**费用护栏**：运行器固定 `FINAGENT_MODE=mock`，**不产生任何模型费用**。
所有 live 入口（`evaluate.ps1`、`model-smoke.ps1`、`rehearse.ps1` 等）都必须显式触发。

## 五、五分钟手工演示（照着敲就能感受全貌）

```powershell

.\scripts\dev.ps1 -Mode mock

| # | 你输入 / 你点击 | 你应该看到 |
| --- | --- | --- |
| 1 | 看顶部 | MOCK、2026-09-24、活期 10,000.00 / 储蓄 20,000.00、卡尾号 1234 正常 |

| 10 | 「从活期账户给张三转100元」 | **追问**选尾号（3821 / 9156），不猜 |

## 六、本次盘点发现的覆盖缺口（已关闭 8 条，仍待补 9 条）

每条都经源码逐文件核对，不是印象。完整 17 条见 `docs\TESTPLAN-INVENTORY.md`。

| 编号 | 缺口 | 建议 |
| --- | --- | --- |
| **G02** | `API.md` 列了 `PROPOSAL_CANCELLED`，但后端**从不返回**；取消后再确认实际是 `INVALID_PROPOSAL_STATE` | 统一契约并固化断言 |
| **G03** | `INSUFFICIENT_FUNDS` 出现 4 处却**零断言**（准备与确认都没有） | 两阶段都断言错误码 + 无写入 |
| **G04** | 会话 **8 小时过期**分支从未被推进到过期点 | 改写 `expires_at_utc` 为过去时间后断言 401 |
| **G07** | HTTP 层 `PROPOSAL_EXPIRED` 分支未覆盖（只测了领域函数） | 经 `TestClient` 走路由断言 409 |
| **G08** | 前端轮询/终态停止/失效读取丢弃/超时**只靠 Playwright 覆盖**，无 JS 单元测试 | 抽依赖后用 `node:test` 写纯单元测试 |
| **G10** | 日转账额度的**上海日切边界**无测试 | 测 00:00:00 / 23:59:59 / 次日重置 |
| **G15** | 一个用例在项目 `var\` 下建临时目录，只读环境会失败 | 改用 `tmp_path` |
| **G17** | 前端金额解析与上限拒绝**无自动化测试** | 抽成模块后用 `node:test` 覆盖边界 |

**另外一处文档漂移**：`docs\TESTPLAN.md` 7.4 节更正了我最初的一个错误判断
——领域层的整数分、双时钟、退款归属**已经有测试覆盖**，真实缺口只有日切与分页边界。

## 七、怎么用这套方案（两种方式，都不必先装）

### 方式 A：直接在外部目录运行（推荐，零改动）

不需要把任何文件复制进项目，只要告诉它项目在哪：

```powershell
cd <本交付目录>
.\scripts\verify-deliverable.ps1 -Tier quick        # 约 7 秒
.\scripts\verify-deliverable.ps1 -Tier standard     # 约 30 秒，全部 113 项
.\scripts\verify-deliverable.ps1 -Tier full         # 追加浏览器验收（需 Edge 与空闲端口）
```

默认项目根目录是 `D:\finagent`，可用 `-ProjectRoot` 改。报告会写到
`D:\finagent\var\testplan\latest\`；**若项目目录不可写，会自动降级**到
`%USERPROFILE%\finagent-testplan\<时间戳>\` 并打印回填命令，不会因此失败。

### 方式 B：装进项目（可选）

```powershell
pwsh -File .\scripts\install-testplan.ps1
```

它会复制文件、重新生成矩阵、跑一次 quick 验证。

> ⚠️ `install-testplan.ps1` **只在你确认项目目录不可写时**才申请一次提权（会弹 UAC），
> 作用是给当前用户补上 `<项目>` 目录的"修改"权限 —— 不夺取所有权、不改动任何文件内容。
> 如果你不想让脚本动权限，可以自己以管理员身份执行这条等价命令：
>
> ```powershell
> icacls "D:\finagent" /grant "$env:USERDOMAIN\$env:USERNAME:(OI)(CI)M" /T /C
> ```
>
> 或者干脆只用方式 A，手工把 `docs\`、`scripts\testplan.ps1`、`tools\` 复制进项目。
> **不装也完全不影响使用。**

## 九、明确不测的范围（避免过度声称）

依据项目自己的 `ARCHITECTURE.md` 与 `EVALUATION.md` 限制：

- ❌ 真实身份认证、真实支付通道、真实资金
- ❌ 生产部署、多租户、隐私合规、风控、运维
- ❌ 任意自然语言规划与开放式对话准确率
- ❌ 人类效率提升 / 用户完成率（自动化耗时不含人的阅读思考）
- ❌ 跨物理机器的复现、真实 API 费用账单

**措辞纪律**：可以说"在已测试场景下无未确认写入、无重复业务结果、UI 与持久状态一致"；
**不能**说"所有输入都正确"。全部账户、卡片、姓名与交易均为合成演示数据。
