# 复杂财务问题规划与综合分析改进

本次在最新版 FinAgent 上增强通用的个人财务规划能力。旅游只是验收用例之一，同一机制也用于储蓄购置、离职过渡、收入变化和订阅节省。代码先在独立数据库及测试服务验证，再备份安装；配置和正式金融数据保持原样。

## 回答应当怎样组织

先识别用户要做的决策，沿用前文已经说明的目标；查阅与目标有关的可用资金、完整月份消费习惯、收入及现金流、资产负债和必要的合同证据；明确区分用户条件、情景假设、导入快照及未知项；经过服务端计算后给出取舍建议，最后只追问最影响结论的少量信息。

例如用户提出旅行，再要求“根据我的存款、日常消费习惯建议”，应分析能动用的现金和通常生活开销，指出消费中可能调整的项目，核对近期必付款与应急要求。未提供报价和总预算时，不编造旅费或直接断言负担得起；提供预算和预留要求后，再核算余量及缺口。

## 主要实现

- 新增只读 `financial_planning_basis` 工具。从本人全量账本计算最近若干完整自然月的消费、退款、收入、现金流、消费分类习惯和波动。默认最近三个完整月，最长十二个月；缺失月份不按零计算，也不把当前不完整月外推。
- 可用活期扣除预留，排除定期及非活跃账户。定期、基金、贷款、信用卡欠款和其他导入档案保留快照属性；信用额度不作为可用资产。
- 模型在统一语义协议中生成 `dialogue.workflow` DAG。每个节点有编号、工具、严格 JSON 参数和依赖，最后为综合回答。整图先校验后执行，拒绝循环、未定义依赖、未知工具、写工具和夹带写目标；最多八个节点、六个读取。
- 计算支持明确的财务用途：生活费预留、目标资金余量、储蓄进度、无收入资金覆盖、收入下降情景。收入下降按“原净现金流减去减少的收入”计算，不把净现金流直接乘收入比例；资金缺口方向由服务端标明。一般算术结果不自动变成财务结论。
- 数字由服务端带项目标签统一展示，模型写简短的判断、取舍和追问，不在自由文本中重写金额或插入金额占位符，避免把正确数值挂到错误项目。回答引用必须来自本轮成功证据，拒绝编造金额、执行结果和收益保证。
- 修复咨询分支过滤消费工具的问题，也避免公共规划中的数字列表序号被当作金融金额而整体拒绝。
- 将图和检查点保存在任务上下文，实际查询保留在持久步骤中；对话页面可展开查看节点、依赖和结果状态，支持手机布局。

## 权限和中断

模型只能选择现有本人查询工具及受限计算，不能获得确认、验证码、提交或执行工具，也不能运行生成的脚本、SQL或任意 API。

需要受保护订阅数据时，工作流停在对话中的查询确认卡。用户手动确认后继续同一图；恢复前校验用户、会话、数据版本、计划版本、检查点时效和任务控制状态，并重新查询业务数据、重算派生值，避免使用等待确认前的旧余额。重复确认不重复启动查询流程；新问题会替换旧待确认问题。

订阅查询授权只允许查询。设置提醒、解除代扣、转账、申购等继续经过原有固定操作单、人工确认和必要的独立验证。查询证据及聊天中的“确认”均不等于办理授权。模型调用期间不持有数据库写锁，问题或操作单变化后不应用迟到回答。

## 验证

- 后端全量回归：278 项通过，另有 4 个子测试通过。最终数值展示调整后，相关工作流与咨询专项再次验证：84 项通过。
- 前端 TypeScript 检查和 Vite 生产构建通过。
- 浏览器：4 项新增工作流检查和 9 项原有转账/即时消息/授权检查通过，覆盖桌面、手机、查询确认、付款账户、丢失响应及跨用户清理。
- 最终真实 DeepSeek 验收包含七轮问题：旅游目标、结合个人信息追问、预算与预留测算、半年购车储蓄、离职缓冲、订阅节省、收入下降。订阅先等待人工查询确认，再继续分析。收入下降场景修正了真实知识库引用被误拦的问题后单独复测通过；原始失败及复测均保留。还验证了前端自动新建任务后的目标继承，其中未获用户原文支持的可选测算被拒绝，其他分析保留。具体回答、DAG、调用和耗时见 `var/reviews/reasoning-workflow-20261016/live-acceptance-final.json`。
- 所有真实模型回放均使用隔离的合成案例数据库；余额、流水、卡状态及所检查的金融业务表哈希保持不变。正式安装另核对整个数据库和 `.env` 未变化。

验收过程中还修正了模型补入未知预算占位、差额方向反解、将目标期限当作预留期限、公共列表被误拦、授权后重复索要确认和金额标签错配等问题。探索性失败输出保留在隔离工作区，发布以最终验收为准。

## 当前边界

这是可审计、有预算和权限边界的只读规划工作流。复杂的多项写业务仍须澄清并进入既有固定单流程。没有接入真实旅游报价、汇率或市场产品数据；当前案例金融数据截至演示日期，历史模式不保证未来。对于资料缺失、查询失败或模型不可用，会保留可核验事实并明确未完成部分，不伪装成功或切换为 Mock。
