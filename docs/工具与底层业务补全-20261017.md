# 工具与底层业务补全

本轮将工具扩展至 62 个，补齐模拟借记卡补发、信用卡授信调整申请与审批、本地商户会员续订取消，并接入查询、对话确认和审计。保留当前 LLM 动态调用工具的架构，未做通用 DAG 改造。

## 本轮新增

| 工具 | 行为 | 权限与实际结果 |
|---|---|---|
| prepare_card_replacement | 补发已挂失的本人模拟借记卡 | 红色强验证、固定单确认后补发；原卡永久停用，资金账户不变；冻结、支付限制及单笔限额保留，代扣不迁移 |
| prepare_credit_limit_change | 申请改变信用卡授信总额度 | 红色强验证后仅提交；独立本机模拟审批员通过后才更新模拟额度，审批拒绝不改额度 |
| prepare_merchant_contract_cancel | 取消指定本地模拟会员的下期续订 | 先黄色查询确认，再独立黄色办理确认；不退款，不提前结束本期权益，不撤销银行代扣 |
| read_service_requests | 查服务单及审批回执 | 普通本人记录自动查询，会员记录仍需订阅查询确认；缺授权时默认不返回会员记录 |

## 可复现流程

- 补卡：先挂失，再对话说“补发尾号 XXXX 的借记卡”，在对话固定单完成强验证及确认。该能力是本地模拟借记卡补发，不包含信用卡补发、实体制卡和邮寄。
- 调额：说“申请把尾号 XXXX 信用卡授信额度改为 20000 元”，在对话强验证提交。在卡片管理的“补卡与授信申请记录”打开独立模拟审批，填写通过或拒绝理由。独立审批员凭据仍由 scripts/approver-key.ps1 管理，不向模型开放。
- 取消会员：说“取消某服务的商户会员续订，保留本期权益”，确认查询范围后，再核对单独的会员续订取消固定单。取消后“下次计划”为空；权益日期沿用原档案，已过期权益不会延长。

## 安全与数据口径

所有新工具只准备固定单或查询；模型没有确认、验证码、审批凭据及执行工具。字段须得到本轮原话或明确未完成草稿支持，未知对象及金额会追问。否定、外币、无法满足的条件和未来执行要求不被丢弃。改单使旧单失效；暂停、取消、过期、来源变化及跨用户请求不能执行；重复确认及审批只返回原回执。

新增 service_requests、credit_facilities 和 merchant_contract_states 三张表。原始年度金融档案、交易流水和余额不改写。审批后的授信与可用额度以本地模拟覆盖层展示，可用额度为原快照加已批差额，仍不是实时银行可刷额度。会员取消通过本地模拟商户生效，不能声称真实平台会员已取消；后台也会停止对已取消合同发起下一期模拟扣费。

## 验证

完整后端回归 380 项通过，年度数据库从原始 CSV 在全新测试库导入，避免正式案例已有操作影响固定基线。最终定向回归 108 项通过，另补充条件语义验证。前端 TypeScript 与生产构建通过，原 API 安全回归 16 项通过。

真实 DeepSeek 已验证三个专用工具停在正确确认步骤，并在全新隔离案例完成本人确认、强验证、审批与回执解读。正式库不用于执行测试。迁移副本保留所有已有业务行，外键和数据库完整性通过。

| 工具 | 用途 |

### 卡片管理

| 工具 | 用途 |
|---|---|
| prepare_card_replacement | 补发已经挂失的本人模拟借记卡。card为用户明确的尾号或名称，只准备红色强验证固定单；确认后本地补发，原卡永久失效，限制保留、账户资金不变，不迁移代扣。不是信用卡补发或真实实体卡配送。 |
| prepare_credit_limit_change | 申请本人信用卡授信额度调整，card为用户明确的卡尾号，amount_yuan为申请新总额度而非增量。红色强验证后只提交申请，须独立审批；模型不能审批或保证获批。与单笔交易限额不同。 |
| read_credit_cards | 查询本人导入信用卡的总额度、档案欠款、可用额度、已出账/未出账和最近账单及还款日。card可填本人卡尾号、名称或id，不填查询全部本人信用卡；缺失返回未知，标明快照日期，不代表实时可刷额度，不办理调额或还款。 |
| list_cards | 列出当前用户的卡片和状态。 |
| read_card_management | 读取本人的卡片限制和办理记录。 |
| prepare_card_loss | 挂失银行卡：用户明确说挂失、银行卡丢了时调用，未知卡片可留空并询问尾号。准备红色强验证固定单，用户手动确认后才挂失；不能用冻结代替挂失，导入只读信用卡不支持办理。 |
| prepare_card_unloss | 解除本人指定卡片的挂失，必须明确解挂意图。仅准备红色强验证固定单，手动确认后才解挂；不解冻、不恢复线上支付、不提高限额，不补卡。 |
| prepare_card_freeze | 冻结指定本人卡片，先准备固定单供本人确认；用户只查询或假设丢卡时不调用。 |
| prepare_card_unfreeze | 解冻指定本人卡片，需要强验证。解冻不能解除挂失，也不能恢复银行授信。 |
| prepare_virtual_card_application | 申请本人虚拟借记卡，source关联账户、applicant本人姓名或本人；准备黄色确认单，提交申请后仍等待独立审批，不能声称已发卡。 |
| prepare_card_limit_change | 调整本人卡片单笔交易限额，amount_yuan为新限额，不是旧值；提高限额需要强验证。这不是信用卡授信额度申请。 |
| prepare_online_payment_block | 关闭指定卡片的线上支付/网购交易，保留线下状态；准备本人确认单，不等于冻结整张卡。 |
| prepare_online_payment_unblock | 恢复指定卡片线上支付，准备红色强验证固定单；仍受整卡冻结、挂失和单笔限额约束。 |
| prepare_card_action | 准备冻结/解冻固定单，action仅freeze/unfreeze。不要把挂失或线上限制当成冻结。 |
| prepare_card_management | 准备虚拟卡申请、限额调整、线上限制或挂失。未知字段不猜，由固定表单继续核对。 |
