# FinAgent 本地部署与故障恢复

基线：2026-10-15，Windows本地模拟演示。后端Python3.12—3.14；本机使用项目 `.venv` Python3.13。前端Node24/npm11，本机便携Node位于 `var/tools/node-v24.22.0-win-x64`。锁定依赖见两个lock文件，`pip check`与本次测试另见验收记录。

## 安装与启动

从finagent目录运行setup，首次且数据库不存在才reset：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
# 仅首次建立全新演示集；已有库不得重复reset
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\reset-demo.ps1 -Date 2026-09-24
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Mode mock
```

首次依赖安装需联网。缺少全局Node时先运行 `scripts/setup-node.ps1`。双击 `FinAgent.exe` 也可选择模式。Live在本地`.env`配置DeepSeek后以 `-Mode live` 启动；修改配置须重启，启动器传入模式优先于`.env`默认值。访问 `http://127.0.0.1:5173`，后端8000，均只绑定本机。

启动检查依赖、已有库与端口，并做增量迁移。端口占用时不杀未知进程；关闭之前的本项目启动器/终端后重试。关闭启动器或Ctrl+C会清理自身服务。日志在var/logs，API Key不进入前端。

## 验证与角色

选择合成用户，Live可点击“检查DeepSeek连接”。旧任务保留原模式；取消未结束旧任务后新建。查询自动执行，写操作必须核对固定单。红色验证在独立弹窗获取模拟短信，用另一终端 `scripts/auth-code.ps1` 读取本机模拟收件箱，不能把验证码发给模型。

本机模拟坐席用 `scripts/operator-key.ps1`；独立模拟审批员用 `scripts/approver-key.ps1`。凭据分别输入相应密码框，不共用、不记录到截图。可由受信任部署环境用 `FINAGENT_APPROVER_KEY_FILE` 指定审批密钥路径；该值不能由聊天或HTTP输入设置。OS管理员不在当前角色隔离威胁模型内。

## 备份、迁移与恢复

1. 停止本项目服务，保留数据库、版本和必要运行配置。
2. 使用SQLite备份接口复制 `var/finagent.sqlite3` 到自定备份文件；不要在写入时只复制数据库主文件而忽略事务。
3. 更新源码后正常启动自动迁移，不reset。旧0006模式重建fixture和0012升级都有隔离回归；真实历史库仍须单独备份与核对。
4. 故障后首先读取原任务、操作单和业务回执。响应丢失可能发生在提交后，不能以重新创建转账排错。
5. worker重启从持久状态恢复；重复扫描依靠业务去重。授权改变、锁定、余额不足需解释原因，不能扩大授权静默重试。
6. 已执行资金结果不假回滚，未付款操作可取消；当前没有通用自动退款/补偿能力。

## 排错表

| 现象 | 检查与处理 |
|---|---|
| 尚未初始化演示数据 | 核实路径确实不存在才首次reset；已有库先备份与定位 |
| 8000/5173占用 | 关闭旧启动器；不关闭未知服务 |
| DeepSeek401/402/429 | 分别更新密钥并重启、检查余额、等待限流；不把模型失败计作用户认证攻击 |
| 未看到确认卡 | 重新查询任务状态或刷新；不要重新POST创建同笔业务 |
| 旧确认单失效 | 核对金额、对象、问卷、版本及期限，重新准备并重新验证 |
| 15分钟安全锁 | 查询/撤销仍可用；等待真实冷却，不能改演示钟解除 |
| Vite spawn EPERM | 属受管执行环境子进程限制；在获准的本机终端运行，不能改业务权限绕过 |

Docker配置仅为候选，未实跑不能作为容器隔离验收。当前验证不替代干净机器另一组员复现或线上银行部署。
