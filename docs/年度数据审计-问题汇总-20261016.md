## 最应先处理的结果

1. Agent识别订阅后，会把该用户订阅接口读坏，页面HTTP500，重新确认查询也不能恢复（F01）。
2. “全部消费”目前只有现金口径，漏信用卡；模型还实测声称信用卡已包含、覆盖完整（F02、F03）。
3. 核心工具目录被截断，订阅分析无专用事实摘要，年度上下文装不下现有明细（F04—F06）。
4. 日期、卡片和“未分类”筛选存在能直接改变结果的缺陷（F07—F11）。

这些问题中有一部分正来自上一轮年度数据适配与原有架构的交界处，不是单纯换更强模型就能消除。当前应优先保证可查询、口径正确和答案忠于证据，再增加分析表现。

### F01 · P0 · 识别一次订阅后，订阅页面接口持续500

**状态：**已复现（真实模型＋页面）。**性质：**缺陷。

真实模型经统一工具调用 identify_subscriptions 后，随后读取该用户订阅概览会崩溃。影响年度合同、银行授权、提醒和历史扣费整块区域；不只是少显示一两条。错误记录按 owner/dataset 选最新，不限当前会话，重新登录不能消除同一数据版本内的坏结果。

**证据/复现：**R06—R09 的识别步骤保存列表。GET /api/subscriptions 对 u1 实测500；Edge页面同时显示“订阅查询已确认”和“服务暂时不可用”。栈为 AttributeError: list object has no attribute get。

**原因：**registry 的 identify 分支返回列表，统一记录器原样存 result_json；get_portfolio 仍假定旧格式对象并调用 .get("candidates")。

**待改进与验收：**旧对象、新列表、空列表均能读取；Agent识别后立即刷新/重新登录，合同、候选、历史全部可用，接口不500。

### F02 · P0 · “全部消费”漏掉信用卡消费与信用卡订阅

**待改进与验收：**建立跨现金/信用卡费用口径；u2上述期间对账为11,268.08元；还款仍不重复算消费；覆盖状态明确列出现金、信用卡与缺口。

### F03 · P0 · 模型能把“未包含的信用卡”说成“已计入且完整”

**状态：**已复现（真实模型）。**性质：**缺陷。
