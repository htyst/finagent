# 四项审查问题修复与复测

日期：2026-09-27。目录：本交接包内的 finagent。无结构迁移，不需要重置主数据库；重启此目录的前后端后使用新代码。

## 行为变化

1. **修改与插话**：先发“如果本月餐饮超过500元，就从活期转100元到储蓄账户”，再发“先查一下账户余额”，返回真实余额并保留原单；再发“改成低于500元才转”，改按严格小于计算。基准净消费1200元时条件不成立，无可确认转账，原单失效。带“可以吗”的条件修改也按修改处理。未知条件（如不超过、去年、无法识别的账户、余额条件）停止旧单并要求重新说明。
2. **取消竞态**：保存发起模型请求时的任务更新时间；模型返回后，在 SQLite 写事务中重新加载并验证该版本、终态、停止标志，随后原子保存操作单/步骤/回复。取消先落库则迟到成功和错误均不再恢复任务；更新消息也使较旧回答失效。没有在网络等待期间持有写锁。
3. **追加条件**：普通转账待确认或补充信息期间，可在原对话补充“加个条件：本月餐饮超过500元”。继承已确定金额和收付款对象，转为条件任务，撤销旧操作单及其确认资格，再核验条件。
4. **流水证据**：查询“上个月餐饮流水”时，助手步骤直接显示对应日期、类别、商户、收支、状态和退款关联；按原查询条件翻页。页面其他筛选编辑不影响该查询，任务切换和刷新不会残留上一任务的明细。

## 测试结果

- 完整后端：**103 passed**，约30秒，包括此前旧库重复迁移测试。保留1条既有 Starlette/httpx 弃用警告。
- 新增后端回归文件 `backend/tests/test_review_fixes.py`：19 项，覆盖 mock/受控 live 条件修订与转换、未知修改、真实双客户端并发取消（迟到成功/错误，有/无旧单）、后发消息优先、流水参数恢复，以及小于条件的确认前重算。使用与生产相同的 `expire_on_commit=False` 检查 ORM 缓存问题。
- TypeScript/Vite 构建：通过。
- 页面回归：**6 passed**。新用例覆盖21条流水翻页、筛选保持、前后页、不同任务及刷新恢复；其余为既有用户切换和统计筛选回归。
- M5 Edge mock：独立端口通过条件展示、按钮确认转账、候选交易选择、拒绝冻结继续余额、冻结后查余额、刷新恢复和用户隔离。只重置 `var/m5-browser-mock.sqlite3` 测试库；没有重置主库。

## 复测命令

在项目根目录 PowerShell 执行：

```powershell
$env:PYTHONPATH='backend'
$env:PYTHONDONTWRITEBYTECODE='1'
$env:FINAGENT_MODE='mock'
.\.venv\Scripts\python.exe -m pytest backend/tests -q -p no:cacheprovider --tb=short
npm.cmd run build --prefix frontend
npm.cmd run browser:regression --prefix frontend
.\scripts\browser-m5.ps1 -Mode mock -ApiPort 18027 -FrontendPort 15127
```

M5 脚本新增可选端口，默认仍为8000/5173；前端开发代理支持 `FINAGENT_API_PROXY_TARGET`，浏览器测试支持 `FINAGENT_TEST_BASE_URL`。本机默认端口存在旧服务，首次检查后端启动失败，因此该次结果未计入验收；上述独立端口重跑才是有效证据。

## 范围

本轮没有调用真实 DeepSeek API；live 分支使用受控响应，保证并发顺序可重复。结果证明这些代码路径及页面修复，不代表任意自然语言理解准确率。仍只支持受限消费条件，未知或复杂条件会追问；所有业务执行继续要求页面确认。
