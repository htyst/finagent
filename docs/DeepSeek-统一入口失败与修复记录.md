# 统一语义入口：失败、修复及证据边界

日期：2026-10-15。所有失败运行保留在 `var/TEST-ONLY`；源码包只附安全报告，排除运行库、日志和认证收件箱。最终结果见 [验收文档](DeepSeek-统一语义入口改造与验收.md)。不删除安全测试以取得通过，也不把不同版本零散通过拼成一次全量通过。

| 发现 | 实际原因及处理 | 证据 |
|---|---|---|
| 旧HTTP安全用例模型迭代器耗尽 | 新协议普通聊天“确认”也要先理解；给原测试补一条语义决策，继续断言聊天不授权，未删除原确认/MFA检查 | `dialogue-first.xml`失败；后续兼容及完整回归通过 |
| 初始同名测试无操作单 | 替身测试写了种子不存在的9001/9002尾号，改用3821/9156；与后续真实模型缺陷分别记录 | `dialogue-scenarios-first.xml` |
| 新上下文消息丢失 | 证据压缩器误删messages键；恢复最近消息，并在后续审查发现800字符裁剪后补齐1000字符用户原文回归 | 替身上下文及长消息测试通过；不宣称真实长会话已全面覆盖 |
| 缺字段后补齐仍要求收款人 | 提前澄清分支没有持久保存已明确字段；改由现有确定性流程保存草稿再只追问缺项 | [首轮5组2通过](evidence/unified-live-first.json)，修复后U02及最终整组通过 |
| 同名尾号选择仍重复询问，或被解释成“备注” | 模型重复旧姓名/错误填target_note；后端在模型先识别业务后进行标识格式和目录核对，清除缺少用户备注依据的猜测；否定旧对象后不得复用旧对象 | 真实中间U03失败、独立新回归用例、最终U03通过 |
| 账单用真实10月代替演示9月 | 同时有实时now_utc和demo_date；改用现有analytics规则规范化账单日期，预约仍使用原业务时钟，不将所有业务统一成假日期 | [扩展首轮](evidence/unified-live-expanded-first.json)、最终U07通过 |
| 账单先查逐笔证据被过严拒绝 | 工具与意图必须同名的限制误伤合理证据读取；允许受限支持性读取，但统计数额必须经后端统计工具，继续严格参数及归属检查 | 中间失败运行保留，最终U07及真实浏览器账单追问通过 |
| 卡片修改只返回用户消息 | 正常只读同步每次更新任务修订时间，导致模型响应被误判迟到；仅真实状态变化才更新时间，自己的受控同步后重新记录修订点 | 真实U08初始失败，三领域同步修复及轮询回归通过 |
| 知识回答没有检索出处 | 模型虽识别knowledge但未请求检索；后端对知识行为要求本地检索，将真实来源交回模型 | 最终U10通过，订阅知识不绕过动态订阅黄色授权 |
| 工具/行为字段放在错误层级或参数类型不合法 | 标准接口采用相关字段输出，保留严格JSON及Pydantic；明确dialogue嵌套协议与例子，格式修复只提供字段名/类型，不使用eval或接受部分非法结果 | [中间整组12/13](evidence/unified-live-intermediate.json)、[定向U05修复后](evidence/unified-live-retest.json)、[最终同版本13/13](evidence/unified-live.json) |
| 初次真实浏览器一直等待 | 等到了资料表单submit，后来又错误要求空输入时“发送”按钮必须可用；改为等待实际HTTP响应及下一次可操作控件，保留失败日志 | `p1-browser-869c...`、`f6be...`失败；最终实际浏览器8项通过 |
| 沙箱阻止本地进程或联网 | Node/Vite测试辅助进程spawn EPERM、真实API在受限环境连接失败；按要求申请受控本地执行，获准后实际运行，不把环境失败算模型通过 | 初始受限调用及工具记录；14项API、Vite及真实模型均随后实跑 |

最后完整API运行使用13组25轮、全局60次请求硬上限，实际36次请求且13/13通过。此前完整运行曾12/13，个别未通过属于模型协议错误，均没有未经授权执行。最终浏览器独立使用17次真实请求，完成黄色确认及提交后丢响应恢复，不把Mock红色弹窗测试冒充真实模型红色全流程。

模型仍可能返回格式错误或理解不准确，服务端会明确失败并保留只读状态/控制能力；此次修复不证明任意输入不会失败。独立人工审定、保留集盲测、全部真实故障及高并发压力仍未完成。
