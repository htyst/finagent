## 本次改动

- 统一对话理解、受控工具选择、复合 DAG 规划的模型配置与请求适配器 `backend/app/agent/model_client.py`。空模型名或空地址采用默认值，支持 `MODEL_API_KEY` 和 `DEEPSEEK_API_KEY`，仅向官方 HTTPS 地址发送密钥，不跟随重定向。
- 默认标准接口 `https://api.deepseek.com`；强制指定工具调用时关闭思考模式。标准接口不启用服务端 Beta strict 参数，但返回值仍须本地 Pydantic 严格校验；显式选择 `/beta` 时才启用 strict。
- 密钥无效、余额不足、限流、无效模型/请求、网络失败分别给出可操作的错误提示。不反射供应商响应原文，避免请求片段和认证信息泄露。规划中的认证等错误直接终止，不作为业务 DAG 格式错误反复修复。
- 补齐通用 Live 理解到理财、卡片管理、订阅、生日、预约及 AA 专用流程的语义路由。命中关键词的成熟流程继续工作；未命中关键词而被模型识别的意图也会进入对应业务校验。复用已经校验的理解结果，不重复保存消息，不重复调用模型，不在持有数据库写锁时调用外部模型。
- 对话框显示 Live 模型名称及本地配置状态，新增“检查 DeepSeek 连接”。后端探测接口要求有效会话、Origin 和 CSRF，使用独立简短工具调用，不发送账户数据、不创建交易。配置状态表示密钥存在，不表示密钥已被供应商接受。
- API 密钥样式文本在聊天持久化和模型输入中脱敏；`.env` 加入忽略规则。密钥不出现在示例文件、前端配置和验收证据中。`httpx` 补入运行依赖声明。

## 业务与赛题权限保持情况

- 余额、账单等绿色查询由业务服务返回实际模拟数据，模型不能自行编造结果。
- 小额转账只能准备固定操作单，聊天“确认”不会执行；页面确认后才执行一次。
- 日累计含本笔超过1000元的转账以及放宽卡片限制仍为红色，缺少强验证时即使取得普通确认令牌仍不能执行。
- 订阅查询须专项黄色确认，模型路由不能绕过。缺少日期、成员、账户等信息时继续追问，不将模糊要求降级成可以立即扣款的操作。
- 金融操作、短信验证和银行接口仍为本地模拟。模型真实联网与银行真实联网是两回事；本次没有接入真实银行交易。

## 本地启动

从外层工作区目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\finagent\scripts\dev.ps1 -Mode live
```

或双击 `finagent/FinAgent-Live.exe`。模式由启动器显式传入；`.env` 的默认 Mock 值不覆盖 `-Mode live`。首次数据已存在，不应再次 reset。启动仅迁移结构，保留数据。

页面：<http://127.0.0.1:5173>；后端：<http://127.0.0.1:8000>。停止当前模式后再启动另一模式，避免端口占用。已有未结束 Mock 任务仍保持 Mock；取消后新建需求即可使用 Live。修改 `.env` 后须重启进程。

- 本次 Live 前后端已实际启动。`/api/demo/info` 返回 `mode=live`、DeepSeek、密钥已配置；页面和 Vite API 代理均返回200。演示日期仍为2026-09-24，数据库未重置。
- 完整后端回归86项通过，另4个子测试通过；其中DeepSeek专项26项通过（是86项的子集）。证据为 `evidence/deepseek-regression.xml`、`evidence/deepseek-offline.xml`。专项测试包含真实应用 HTTP 路由与替身模型：查询结果等于账户接口返回、准备不扣款、聊天确认不扣款、黄色页面确认执行、红色缺验证被拒绝。
- TypeScript 完整类型检查通过；前端 API 回归14项通过。页面和模块可加载不等同于浏览器交互全量验收，浏览器 E2E 和生产构建本轮未重新验证。
- 本机启动与源码密钥排查记录为 `evidence/deepseek-local-startup.json`；实际密钥未在可分发源码中出现，本地 `.env` 不进入源码包。
- 真实 DeepSeek 探测在沙箱中连接失败；沙箱外真实探测未获批准，因此无法确认本地密钥的供应商认证、余额和实际对话响应。未通过其他通道绕过此限制调用真实模型。Live 服务启动获准且启动过程不请求模型。用户可在本机页面主动点击连接检查完成最后一项。
- 后端现有两类测试警告分别是关闭 pytest 缓存插件后的配置提示和 Starlette 的 httpx 适配弃用提示；不是测试失败。
