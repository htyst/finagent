# 设计决策

## D001｜开发依据与阶段

- 日期：2026-09-24
- v2.0 完整替代 v1.0 的开发规格；两版原文件保留。顺序为 M0→M7，每阶段实际验收后推进。
- 原因：v2.0 固定了统计、转账、确认和恢复语义，减少实现歧义。

## D002｜本地技术路径

- 前端采用 React、TypeScript、Vite 与 npm lockfile；后端采用 Python、FastAPI、Pydantic、SQLAlchemy、Alembic、SQLite，项目独立 `.venv`。仅在 M1 建立真实依赖文件并锁定经验证版本。
- 数据库默认位于项目 `var/finagent.sqlite3`，运行数据与 `.env` 不入 Git；测试使用临时数据库。重置脚本仅可操作解析后位于项目 `var/` 内的数据库。
- Windows PowerShell 是首要启动环境。M1 脚本优先使用可用的系统 Python；M0 的沙箱终端未暴露本机 Python；经用户指出并重新检查，实际已安装 Python 3.12.10 与 3.14，M1 采用本机 3.12。脚本需明确可配置 Python 路径，不把 Codex 专属绝对路径写为用户运行前提。
- 当前只决定技术方向，尚未安装依赖或证明应用可启动。

## D003｜模型配置与密钥

- 模式为显式 `mock` 或 `live`，不在 live 失败时自动伪装为 mock。模型配置键：`MODEL_PROVIDER`、`MODEL_NAME`、`MODEL_BASE_URL`、`MODEL_API_KEY`；M1 独立试验证实 `deepseek-flash`、`https://api.deepseek.com/beta` 的严格只读工具调用和缺信息追问可用；当前使用 httpx 直连。完整 Agent 仍在 M4 实现。
- 用户提供的密钥仅放本地 `.env`；仓库只保留无密钥的 `.env.example`。业务与确定性检查不应自动消耗模型额度。

## D004｜执行权与确认

- 模型仅能使用只读和准备工具。确认凭据、提交、取消、重置走应用后端专用路径；聊天文字没有执行授权效力。
- 确认操作单绑定用户、会话、任务、固定参数、资源及数据版本和实际 5 分钟有效期。SQLite 写入采用短事务，提交前复核；成功结果持久化并可幂等查询。
- 一会话最多一个活动写任务，一任务最多一个写操作；受限计划最多 12 步。来源为 v2.0 第 6—8 节。

## D005｜接口与交付边界

- M0 固定 `docs/API.md` 的路径草案，M1 可在实际实现时修正细节但必须记录变化；不改变权限或确认语义。
- 仅合成数据和模拟银行，不接真实银行、支付或身份认证。赛事报名与外部发布需另行授权。
## D006｜M2 统计口径与内部账本服务

- 日期：2026-09-24
- 统计规则版本为 spending-v1。API 日期参数按含首尾日输入，内部转换为上海时区左闭右开 UTC 区间；默认本月至演示日并对比上月同期。自定义主区间默认无比较；需要比较时显式提供自定义基准区间。
- 统计先针对完整匹配记录聚合，再单独分页证据。覆盖缺口可展示已知小计，但不输出完整结论或百分比；基准净额不大于零时差额仍可显示，百分比为空。
- 账本写方法保留在后端内部；M2 不公开执行接口。M3 必须将其包裹在确认、版本复核、事务、幂等与审计链路中。

## D008｜统一后续开发目录

- 日期：2026-09-25。以本仓库 `D:\finagent` 为唯一后续开发目录；同伴副本只作历史参考，不复制其中的 `.env`、`.venv` 或 `var/`。
- 合并保留主项目既有回归，并吸收同伴版更广的日期、类别和受控响应测试、统计筛选提示，以及备份旧虚拟环境的恢复流程。指定 `setup.ps1 -Python` 或 `-Rebuild` 仍按主项目既有约定强制重建。
- 种子版本为 `m2-2026-09-25-1`；默认演示金额和统计口径 `spending-v1` 不变。本次合并仅涉及 M0–M2，M3 尚未开始。

## D009｜M3 确认与本地来源校验

- 日期：2026-09-25。M3 使用 SQLite `BEGIN IMMEDIATE` 序列化写事务；任务唯一活动会话键限制每会话一个待确认写任务。操作单绑定会话、数据版本、固定参数摘要和资源版本快照，真实系统时钟 5 分钟到期。
- 按钮确认分两步：同源页面和会话 CSRF 校验后签发凭据，数据库只存摘要；执行时复核状态、快照、余额与额度，业务、回执和成功审计同一事务提交。重复确认读取持久回执。提交前故障回滚后原单可重试，并另记失败审计。
- 本地 Vite 代理转发后，后端所见 Host 与浏览器 Origin 端口不同；启动脚本显式设置 `FINAGENT_ALLOWED_ORIGIN` 为本地页面来源。未配置时仅接受请求本身同源；仍需会话 CSRF 凭据。

## D010｜M4 单场景 Agent 与 DeepSeek 工具兼容

- 日期：2026-09-25。沿用 M1 已验证的 DeepSeek `deepseek-flash`、`https://api.deepseek.com/beta` 和 httpx；密钥只从被忽略的本地 `.env`/环境读取。mock 使用有限单场景解析器，live 在服务端核实意图与缺项后调用真实模型选择严格工具参数；两者调用相同的查询及 M3 准备服务。
- DeepSeek 严格模式不接受自动生成的目标联合类型与部分可选写参数 schema，模型侧采用无可选字段的最小扁平写工具 schema，后端再转换为互斥目标结构并逐字段比较已核实参数。只读 schema 保持严格校验。确认、取消、凭据及重置不进入模型工具注册表。
- 业务数字和状态由持久结构化结果生成确定性摘要；商户/备注仅作数据，不回灌为模型指令。网络超时 30 秒，临时故障最多重试一次；明确报错而非降级为 mock。开发评估结果记录源文件摘要与提示词摘要。

## D011｜Alembic 版本事务修复

- 日期：2026-09-25。迁移环境设置 SQLite 外键 PRAGMA 后先结束隐式事务，再让 Alembic 管理并提交修订事务。此前旧库表已创建但 `alembic_version` 可为空；修复后幂等重放至 `0003_m4_agent`，保留主库 6 个合成账户。新建库和重复升级均加入回归。


## 2026-09-26｜M5 有限计划与原子恢复

- 以两条企划主故事的服务端计划模板实现跨场景，持久化版本、依赖、输入引用、失败策略和用户请求结果。模型仍只返回经核实的工具核心参数，结构化条件由服务端生成并加入固定摘要。
- 条件复核放在 M3 现有 SQLite 写事务、资源版本验证之前，确保新增退款的判定清楚且不可插入竞争写。Agent 写步骤和业务结果原子提交，准备时原子链接操作单。
- 恢复不调用模型，不重新确认或扣款；独立余额失败只重试余额。全任务取消与单操作拒绝使用不同 UI/API。
- 新增 `0004_m5_plans`；主库无重置升级，6 账户及余额保留。40 条任务按 30/10 划分且去重；对话评测和实际确认的后端/浏览器验收分别记录。


## 2026-09-26｜M6 单份确认与可恢复同步

- 复用 M3/M5 领域逻辑，将同一对话操作单从表单区移除重复展示；手动表单改为可展开入口，对话外的独立操作仍保留自身确认与回执。
- 以共享前端任务同步逻辑管理轮询、停止和网络错误，不增加后台调度。UI 变更依据持久任务/操作单，不推测业务成功；网络异常后只核对原结果。
- 使用预期用户请求头保护共享 Cookie 下的跨标签页展示一致性，服务端身份权限仍以会话为准。前端用户代次、任务读取序号、账户刷新批次分别阻止过期响应。
- 分类图直接使用既有统计 categories 聚合结果，使用正负横条、金额标签和覆盖提示，无外部数据或图表依赖。
- M6 验收入口包含历史浏览器回归与新故障场景，所有数据库故障注入只允许 `var/m6-browser-*`。全量入口拒绝单项筛选，避免局部检查被误报为完整通过。
