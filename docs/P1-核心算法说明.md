# FinAgent 核心算法说明

版本：P1候选，2026-10-15。本文说明实际实现，不以模型内部推理过程作为审计证据。

## 意图、参数与事实

入口为 `agent/service.py`。Mock 使用本地规则；Live 使用 `language.Understanding` 的严格结构模型提取意图和当前明确参数。两种模式最终进入相同领域服务。账户、收款人、卡片必须在当前用户数据范围内唯一匹配；同名、未知号码、缺金额继续追问，模型不能填写 owner_id、authorized 或确认令牌。

金额使用整数分；用户输入十进制字符串经校验转为分，拒绝浮点精度猜测、负数、零或超范围值。中文金额由既有解析器处理。预约使用带时区的真实未来时间；消费分析使用演示日期，安全日累计使用真实上海自然日，三种时钟不能混用。

Live 的关键词分支和语义回退都调用专用业务编译器，回退复用已校验理解结果，外部请求不持有数据库写锁。网络错误保留已有草稿，不能变成成功回执。完整账号和收货资料在本地解析；模型输入另作脱敏，不发送确认材料。

## 目标与有向无环图

`orchestrator.split_goals` 按受支持连接词拆分目标，`resolve_goal` 将目标绑定到白名单工具及实际用户资源。条件、否定、周期或多写不能完整表达时保留需求并追问/要求拆分，不静默办理第一项。

步骤含 ordinal、tool_name、params、goal_id、depends_on、input_refs、on_failure；校验器拒绝未知工具、前向/循环依赖、缺目标、参数改写、引用类型错误及错误业务前置。申购需匹配理财事实读取，卡片写需卡片读取，不能任意读一次即满足前置。

Live 计划最多修复2次，总期限30秒；只对计划结构或语义违规修复。认证、余额、权限、配置和供应商错误直接返回，不能要求模型调整金额绕过。单次解释最多2次尝试；HTTP重试数和计划修复数分别记录，不互相替代。

## 授权与执行

固定操作单保存条款与资源快照摘要。确认时 SQLite `BEGIN IMMEDIATE` 串行化，重查会话、数据版本、余额、累计、资源状态、条件及任务控制。绿色查询直接执行；黄色等待页面明确确认；红色消费一次绑定操作单和条款的180秒模拟短信证明。日累计超过1000元的转账、申购、挂失等按服务端矩阵处理。

后台预约、生日采购、代扣必须匹配持久专项授权，检查次数、期限、条款和用户锁。worker不能自行生成强验证。已结算交易只读恢复，不能通过删流水“回退”；失败的准备可重做，已付款采购需独立补偿流程（当前无通用自动补偿）。

## 各业务规则

| 场景 | 实际算法 | 事实与限制 |
|---|---|---|
| 转账/AA | 姓名、电话、保存备注精确匹配；分摊整除及余分按本人优先顺序分配 | 收款目录不等于真实银行户名核验；AA付款是模拟通道 |
| 账单 | 已入账消费减关联退款；账户覆盖区间合并；按完整月份排名 | 未覆盖月份 totals=null，不能当0；同期退款可使净消费为负 |
| 异常 | 至少5条时检查 max(1000元, 中位数×10)；120秒内同账户/商户/金额重复 | 仅待核实线索，未命中不代表绝对安全 |
| 理财 | 四题0—2分映射R1/R2/R4；匹配风险、起购、期限；整数净值和费用结算 | 三款本地虚构产品，收益非保证；重新评估使旧单失效 |
| 卡片 | 单笔限额、线上开关、整卡冻结、挂失分层校验 | 申请确认后先受理，独立审批员才模拟发卡；挂失不能靠解冻解除 |
| 订阅 | 同账户/商户/金额至少三次连续月份规律消费 | 疑似订阅不等于代扣授权；月底取实际月末，重复期去重 |
| 生日 | 预留减少可用余额但不减少账面；固定商品报价；独立付款/送达状态 | 成功商品不重买；失败蛋糕可单独重试；全部送达后释放剩余专款 |

## 评测边界

`scripts/evaluate-dialogue.py` 分开标记 Mock 与真实 Live；开发集和保留集ID分离。样本标注尚待团队人工复核，不能称人工审定独立测试。记录分母、状态/工具符合率、未授权入账、P50/P95及供应商实际usage；没有账单不估算费用。当前受限DAG不宣称任意自然语言规划全覆盖。
