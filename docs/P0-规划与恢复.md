# P0 规划与恢复

`agent/registry.py` 的统一目录包含账户、流水、账单、理财、卡管、订阅、生日、预约、AA读取/准备适配器，不包含确认、认证、审批、Shell或任意代码工具。身份来自服务端会话，模型不能提供 owner_id、authorized 或绿色等级。

`agent/plans.py` 校验1—12个有序步骤、依赖、环/未来引用、已知工具、Pydantic业务参数、结果引用路径/类型、具体业务读取前置条件及完整目标覆盖。统一计划必须携带参数和目标编号。模型不得改变服务端从用户明确表达解析的金额、对象或条件；结果引用只能佐证已有明确参数，不能替用户选择歧义对象。

`agent/orchestrator.py` 在现有专用业务澄清流程之前处理复合请求。它保留全部目标文本，支持明确的多个读取目标及读取＋单个转账/申购/挂失等准备步骤。Mock构造确定性计划；Live请求模型生成计划，再运行相同验证器。校验失败最多重生成2次，总时限30秒；模型超时或缺配置停止。业务权限、认证、余额或资源失败不进入模型改参修复。

示例：“先查余额，然后查理财持仓”形成两个有序读取；“查余额，然后从明确账户转给明确收款人100元”在参数齐全后准备固定单，等待独立页面确认。未完成查询需在确认成功后发送“继续”恢复，成功写步骤不会重放。

当前不支持任意多写DAG。多写请求会列出完整目标并要求逐项拆分。复合请求中的复杂条件、否定、周期、未明确时间、生日资料补充等若无法安全解析，会保留全部目标并澄清，不丢掉条件后直接执行。已有单场景条件转账、生日资料表单和各业务追问流程继续可用。因此不能把当前实现宣传成所有自然语言都能自动规划成功。

暂停/接管控制保存在独立 `task_controls` 表。UI、领域准备、最终确认和关联后台契约均复验控制状态。模型调用在写事务之外，接收模型响应后仍复验任务状态。暂停时保存计划版本；版本不符则拒绝直接恢复。接管队列仅允许建议/终止/恢复，不能生成用户授权。当前保留已完成账本；回退意味着停止尚未执行步骤，已经付款不删账假装回滚。

本轮模型替身测试已通过，验证有界修复和业务失败不能改参。复合任务确认后仅恢复剩余读取、卡片已在目标状态时不等待不存在的确认单，也已通过回归。真实Live调用、完整自然语言保留集与浏览器多轮恢复仍待实跑；不要把替身测试说成真实模型评测。

每条新消息持久登记请求编号；复合计划安装前在写事务内核对编号及任务状态。新消息、暂停或接管使旧编号失效，暂停后再恢复也不会接纳暂停前尚未返回的复合规划。此保护不代表所有既有Live专用分支已经完成并发压力验收。
