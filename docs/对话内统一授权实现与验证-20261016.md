# 对话内统一授权实现与验证

2026-10-16

## 用户现在可以怎样办理

明确提出业务需求后，助手在当前对话中展示服务端保存的固定办理单。点击“核对并继续”会在当前页面打开安全确认窗口，展示对象、账户、金额、时间、条件与影响。黄色操作需要明确确认；红色操作还需要完成绑定本单的独立模拟短信验证。确认后继续原业务并同步持久状态、回执或后续读取，不需要跳到其他业务页重新提出需求。

| 业务 | 对话内覆盖范围 | 确认后的状态口径 |
| --- | --- | --- |
| 转账、冻结与解冻 | 固定操作单与原有条件校验 | 执行结果和原回执；支持的组合任务继续后续读取 |
| 模拟理财 | 申购、赎回、缺失/过期风险评估 | 评估先继续准备新单，交易另行确认；结果显示已受理或已结算 |
| 卡片管理 | 申请虚拟卡、挂失、限额、线上消费设置 | 申请提交后仍待银行审批，不伪称已经发卡 |
| 订阅与代扣 | 查询授权后继续原提醒或解除需求，再单独确认办理 | 查询授权不会直接设置提醒或解除代扣 |
| 预约转账 | 固定时间、时区、对象及金额 | 已预约不等于已经转账，到期仍由原规则检查 |
| AA 收款 | 成员、份额与收款账户 | 发起后等待成员付款，不把发起当成到账 |
| 生日安排 | 创建、修改、取消、取消商品与重试固定单 | 按原有预留、下单、付款和送达记录展示 |

## 授权前缺少信息时

- 缺订阅查询权限：保存原请求及受限语义字段，先展示本人订阅的短时查询确认。点击后继续核对同一需求并生成办理单；不会在查询确认中执行撤销或提醒。
- 缺有效风险评估：在对话中显示四题问卷，用户按实际情况填写；保留原产品、金额/份额和账户。提交后由原领域规则重新评估并准备新单，随后仍需单独交易授权。评估不能由模型代答。
- 确认时风险要求升级：最多重新展示一次本单安全确认，要求用户完成新的验证；网络错误只读取服务端状态，不自动重放付款。
- 风评不匹配、余额不足、产品锁定、银行审批权限不足、安全冷却等业务限制按原规则处理，不以确认框绕过。

## 完整性与恢复

新增任务专属的条款读取、挑战、验证、凭据签发、确认、取消及风险问卷接口。任务、会话、用户、数据集、操作单、条款快照和计划版本共同约束确认目标。领域提交的写事务内再次验证任务绑定，避免确认前后的版本变化。模型工具目录没有新增授权、验证码或执行工具。

重复点击通过同步互斥与后端持久结果恢复处理；确认响应丢失后读取原状态，不重新付款。取消安全窗口保留未执行草稿；取消本单走原领域取消规则。更换需求、旧单过期、暂停/人工接管和切换用户均受服务端校验；用户切换会关闭原安全窗口。验证码不进入聊天或模型，只输入独立安全窗口。原验证失败计数与锁定逻辑在新增接口中继续生效。

本地模拟短信仍通过原有 `scripts/auth-code.ps1` 私有收件箱读取；没有新增网页获取验证码的接口，也没有把本人确认提升为银行审批权限。已有业务页面的原确认入口继续保留。
