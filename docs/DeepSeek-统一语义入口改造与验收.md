# DeepSeek 统一语义入口改造与验收

日期：2026-10-15。本文对应本轮实际源码，不将此前 P1、Mock 或模型替身通过替代真实 DeepSeek 验收。项目仍是本地合成数据模拟银行；真实调用的是 DeepSeek API，不是真实银行、短信或商户服务。

## 检查发现与改造范围

已检查工作区及上级路径，未找到适用的 AGENTS.md。阅读了 README、模型配置与提示词、聊天 HTTP 入口、上下文构造、工具注册表、通用 DAG 规划器、领域流程、权限/认证/审计/任务控制和既有测试。没有替换整体框架，也没有删除已有安全测试。

原 Live 并非每条业务消息都先走同一模型入口：通用复合任务、生日、订阅、卡片、理财、预约等分支在 `service.send` 内提前用本地文本规则选择流程，各自决定是否调用模型。原模型请求包含最近 16 条消息，并非只发送最新一句；但缺少完整草稿、字段来源、目标清单和工具证据，且结果解释主要依靠各领域模板。

本轮将 Live 普通聊天前移到统一入口。规则继续用于格式规范化、目录消歧、精确金额与日期核对、安全和领域校验；不再在进入模型前替普通聊天选择业务。Mock 保持明确的规则模式。固定资料表单、点击操作单确认、独立验证码、后台任务和紧急停止有各自确定性入口。

## 新旧流程

旧流程：聊天 → 多个文本路由 → 局部模型或规则 → 领域流程 → 结果。

新 Live 流程：聊天 → 认证信息过滤/紧急控制 → DeepSeek 结构化理解 → 只读工具白名单、参数与归属检查 → 读取并保存证据 → 将范围、覆盖和错误交回 DeepSeek → 回答、澄清或交现有领域流程准备固定单 → 用户页面确认/独立强验证 → 原后端执行与回执恢复。

模型没有确认、提交、授权签发、验证通过、代码运行或文件读取工具。`understand_request` 是语义提案，不是执行工具；模型返回合法 JSON 仍需后端业务验证。后台预约、代扣、生日采购沿用已保存授权及后端策略，不调用模型临时决定扣款。

## 上下文与职责

每次请求包含固定系统边界、最近最多 12 条消息、较早对话的带角色摘录、当前任务/计划版本、业务草稿、字段及来源、缺项、原始目标和近期修改、条件/禁止事项/时间要求、固定单摘要、近期证据、允许动作和工具 Schema。较早摘录是有界的原文摘要，不是授权来源。请求超过 64,000 字符会拒绝继续并提示缩小范围，不截断 JSON 后执行业务。

重要事实以服务端草稿和业务资源为准。金额、收款人、账户、卡片和时间等字段有来源、是否明确选择、资源引用等元数据；`approved_fixed_form=false` 明确区分“用户说过/选择过”和“已授权固定单”。不受当前原文或唯一已建立草稿支持的字段不能进入新写单。明确尾号由本人目录核对；姓名或尾号不能被模型变成“已保存备注”。完整账号与生日收货资料仍由本地表单核对。

用户/会话/任务/数据版本每次工具调用和模型返回后重新校验。较早任务只能通过同一用户及原会话的只读引用访问，不能继承已完成交易的授权。密钥只在后端本地配置；验证码、确认令牌、认证秘密、完整账号和已知收货资料不进入模型上下文。自由文本脱敏不是通用 DLP，不能保证识别所有未经标注的个人信息。

## 行为及业务衔接

- `改成800`：关联唯一当前草稿；作废旧单/旧凭据并重新准备。不能把模型推测金额升级为明确事实。
- `不是这个张三`：清除当前目标及旧对象相关槽位，旧单失效；随后可在同名候选中明确选择尾号。
- `先别转，查一下余额`：语义识别后先使旧单失效，再进行可能耗时的查询，保留草稿；不会查询完自动转账。
- `还是刚才那张卡`：只接受同一草稿或唯一结构化历史引用，歧义时追问。
- `刚才那笔成功了吗`：读取原任务/操作单/持久回执，不新建同一交易。
- `算了`：取消当前明确且后端允许取消的部分；多项可取消对象时先问，已完成交易不伪装撤回。
- 多目标：保存完整列表并展示。当前通用计划仍最多一项写操作；多项写或不支持的条件/周期不静默只办理第一项，要求逐项明确。任意自然语言条件尚不能自动编译成完整 DAG。

读取工具沿用参数 Schema、受限 DSL 校验、身份与归属检查。订阅查询/识别继续调用原黄色授权保护，不能以普通读工具旁路。账单相对日期用演示日期；预约等实时业务沿用各自时钟。统计金额必须来自后端统计器，模型可先读取逐笔证据，不能用生成文字作为金额计算或交易依据。

工具证据包含查询参数、时间、范围、覆盖、来源引用、错误代码和后续动作。模型负责简洁解释；金融金额、统计和操作状态优先使用已有业务区域与后端渲染。模型解释若无依据引用、含无依据数字或强成功/盗刷结论，会被拒绝展示并使用实际证据回复。这是保守防护，并非已证明能形式化验证所有自然语言事实。

## 模型协议与运行配置

继续使用已配置的 DeepSeek 官方兼容接口与 Function Calling，`thinking.type=disabled`，不收集或展示内部推理。标准端点使用普通工具协议并在本地严格校验；只有配置 `/beta` 时标记 `strict=true` 并按要求生成严格 Schema。未声称本轮真实测试过 beta 端点。

官方协议依据：[API 入口](https://api-docs.deepseek.com/)、[思考模式及工具协议](https://api-docs.deepseek.com/guides/thinking_mode/)。配置仍由后端 `model_client.configuration()` 校验；本轮未把凭据写入前端或文档。

在 `finagent` 目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Mode live
```

打开 <http://127.0.0.1:5173>，选择演示用户。已有数据库直接启动，不要为了本轮升级重置数据。模型或密钥配置修改后需重启后端；历史任务保留创建时模式。

`.env` 可配置下列非秘密参数，示例已加入 `.env.example`：

```dotenv
DIALOGUE_MAX_MODEL_CALLS=4
DIALOGUE_MAX_TOOLS=6
DIALOGUE_TIMEOUT_SECONDS=55
```

默认每轮最多 4 次实际模型请求（含格式重试及语义修复）、6 次工具调用、55 秒；硬上限分别 6/8/90。格式重试最多 1 次，语义/工具参数修复最多 2 次，仍共用总请求预算。任务持久步骤上限沿用 12，超过后要求新建任务。相同读取不重复运行。超过上限、未知工具、无效参数或引用不能直接准备业务。

DeepSeek 不可用时明确提示 Live 错误，不转 Mock；页面已有状态/回执读取、独立停止、暂停/恢复/人工接管等确定性能力保留。普通聊天恢复仍需模型；模型断网时用页面控制或“紧急停止”。

## 三组实际支持的多轮演示

1. 转账：`从活期账户转100元给张三` → `选尾号3821` → `改成80元` → `先别转，查一下余额` → `原来那笔改成60元，再准备一下` → 在固定单完成黄色确认 → `刚才那笔成功了吗`。第一次准备不是成功；最后读取原持久回执。
2. 账单：`看看本月餐饮花了多少` → `那上个月呢`。在演示日期 2026-09-24 下，上个月是 2026-08-01 至 2026-08-31；保留餐饮类别。其他日期的实际范围由当前演示日期决定。
3. 卡片：`尾号1234这张卡先别让它在网上花钱` → `还是刚才那张卡，把单笔限额改成500元` → 在新限额固定单确认 → 刷新恢复。第一张禁止线上单只有准备，改为限额后旧单失效，不能声称线上限制也已执行。

这些名称和尾号属于本项目合成数据；更换演示用户后使用其本人目录，不跨用户套用。
