# O01/T01：工具契约、审计与页面状态

2026-10-18。复用注册表、Pydantic schema、固定单、授权服务和现有任务审计接口。

## 自动生成与兼容

```powershell
.\.venv\Scripts\python.exe -B scripts/export-tool-contracts.py
```

输出 [当前工具契约](evidence/current-tool-contracts.json)：64 个后端可识别工具，58 个模型可见工具。输入 Schema 来自实际 `dynamic_protocol.models()`；别名/固定动作来自 `ALIASES`；权限与副作用来自受信任 `registry.execution_policy`；版本为规范化内容 SHA-256。通用卡片/预约/AA/订阅旧入口保留校验兼容，新模型请求优先看到专用工具，减少重复入口。

输出 Schema 明确描述**动态循环观察信封**。各领域工具内部 data 并未全部建立静态返回模型，文件逐条标明 `output_schema_scope`，不把通用 object 宣称为完整类型化领域数据。目录的业务分组仍是唯一语义分类表，工具名称全集由代码校验。

`card_management.RULES` 已按 `servicing.py` 实际实现修订：已挂失模拟借记卡可独立强验证补发，原卡永久失效；不代表实体卡配送，不补发导入只读信用卡。

## 关联与隐私

`dynamic_runtime.events` 只保存可核对的节点状态事件：事件 ID、请求 ID、任务/运行 ID、计划版本、节点 ID、目标 ID、工具、参数摘要、证据、资源和回执引用、时间。固定单返回真实 `plan_version`、条款摘要及资源 ID。审计接口 `/api/tasks/{task_id}/audit` 继续验证本人、会话及数据集，关联实际目标图、授权 action ID 与真实回执；不包含确认令牌、验证码、API 密钥或模型私有思维链。

授权关联的 `plan_version` 是当前审计视图版本；历史执行版本应结合节点 `result_plan_version` 与对应事实事件核对。旧授权关联没有逐次签发快照，不能把当前视图版本称为原始签发版本；该审计精度仍需后续完善。

新消息有新请求屏障，后台回调也绑定发起请求，旧回调不能覆盖后续问题。领域与 worker 仍以资源 ID 保留自身事件，并非外部支付系统分布式 tracing。内嵌事件最多保留 256 条，领域幂等、真实回执与原审计独立持久保留。

## 页面行为

- 目标显示待补充、待页面授权、独立验证及确认、执行中、已完成、失败、取消及结果待核实。
- 单独保留已失效和已修复尝试，避免把历史计算显示为当前结论。
- 固定单展示真实版本、条款、有效期、服务端 `can_confirm` 和回执；重复点击仍由既有幂等域执行保证一致。
- 下一条消息继续当前对话，付款完成后的追问仍保留同任务回执；任务取消或到期后需新任务；新对话保留原服务端记录。输入验证码依然只能进入安全窗口。
- 轻量目标摘要和可展开实际调用，无虚构步骤、假完成或模型内部推理。

本轮 Edge 覆盖桌面、390px 窄屏、长回复/多目标、跨轮更正、黄色页面授权和刷新回执。六类领域流程还须结合后端六场景测试；没有把这些测试称为全部场景浏览器验收。
