### MC-02 账户/卡/收款人只读展示

| 项 | 内容 |
| --- | --- |
| 步骤 | 看顶部账户卡、卡片列表、收款人列表 |
| 期望 | 活期 `4082` 10,000.00 / 储蓄 `6105` 20,000.00；卡 `1234`、`5678` 状态正常；收款人 张三 `3821`、张三 `9156`、李文 `7072` |
| 要点 | 只读页面上**不应存在**任何能改变余额或卡状态的控件 |

### MC-03 本月餐饮统计（核心数字）

| 项 | 内容 |
| --- | --- |
| 步骤 | 对话输入"这个月餐饮消费多少？"，展开"消费证据" |
| 期望 | 净消费 **1200.00 元**；消费 **2 笔**、退款 **1 笔**；环比上月同期 **800.00 元**、**+50.0%** |
| 手算 | 1000.00 + 250.00 − 50.00 = 1200.00；上月 900.00 − 100.00 = 800.00；(1200−800)/800 = 50.0% |
| 反例 | 若显示 1250.00（未扣退款）或 1300.00（把上月退款算进本月）→ 统计口径错 |

### MC-04 统计证据下钻与分页

| 期望 | 3 条：`+1000.00`、`+250.00`、`−50.00`，带正负号；合计等于 1200.00；翻页不重复、不丢项 |
| 要点 | 退款条目应**关联到原消费**，并可继承原消费的类别 |

### MC-05 覆盖不完整

## 关于"不写业务"的通用判定

几乎每条写用例都要回答同一个问题：**这次操作到底有没有改变数据库？** 统一核对三张表：

```sql
-- 余额有没有动
select id, balance_minor, version from accounts order by id;
-- 有没有新增业务结果
select count(*) from business_results;
-- 有没有多余的转账单/卡操作单
select count(*) from transfer_orders;   select count(*) from card_action_orders;
```

断言原则：**准备阶段这三项都不变；只有确认成功后才允许变化，且变化必须与回执一致。**
