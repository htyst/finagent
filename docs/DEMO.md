# 演示与交付手册

## 首次启动与演示基准

在项目根目录运行 README 的安装指令。已经有演示业务数据时先保留数据文件，再决定是否重置。下面的重置会清除本项目合成数据，不用于无损升级。

```powershell
.\scripts\reset-demo.ps1 -Date 2026-09-24
.\scripts\dev.ps1 -Mode live
```

选择林晓：活期 10,000 元，储蓄 20,000 元，卡尾号 1234 正常；日期 2026-09-24；页面顶部必须显示 LIVE。准备操作不会改变余额。录像排练使用单独数据库，还额外加入一笔昨晚消费用于展示消歧，不修改主库。

## 五分钟讲解稿

| 时间 | 页面动作与讲解 | 可核对结果 |
| --- | --- | --- |
| 0:00–0:30 | 说明合成账户、模拟业务、LIVE 模型和日期；选林晓 | 10,000 / 20,000 元，尾号 1234 |
| 0:30–1:30 | 输入“这个月餐饮消费多少？”，展示统计与消费/退款证据 | 1,250−50=1,200 元，上月同期 800 元，增长 50% |
| 1:30–3:30 | 输入“昨晚有笔不认识的消费，帮我查是哪张卡；如果是尾号1234，帮我临时冻结它，再告诉我账户可用余额。”核对交易及卡尾号，点击确认 | 1234 卡已冻结；活期仍 10,000 元；逐步结果与真实回执。多笔时先选择“待核对商户” |
| 3:30–4:30 | 输入“如果本月餐饮超过500元，就从活期转100元到储蓄账户。”核对固定条件与目标，再点确认 | 条件为 1,200>500；余额 9,900 / 20,100 元，刷新保留回执 |
| 4:30–5:00 | 展示评估与架构说明：精确统计、业务确认、条件复核、持久恢复 | 说明受限任务范围及本地模拟性质 |

两故事可以独立重置演示；讲解期间不重置。冻结卡片不等于冻结账户，仍允许账户间转账。自动录像以账单→条件转账→拒绝冻结→冻结查余额顺序进行，覆盖额外的拒绝和恢复支线；它是短技术演示，无配音，不是已经按赛事规格制作的成片。

## 主线与备用录像

```powershell
node frontend/node_modules/playwright-core/cli.js install ffmpeg
.\scripts\rehearse.ps1 -Mode live -Repeat 3
.\scripts\rehearse.ps1 -Mode mock -Repeat 1
```

需要本机 Edge（或 FINAGENT_BROWSER_PATH），8000/5173 空闲。输出在 `var/rehearsals/<时间>-<模式>/run-N/`：WebM 录像、逐轮 result.json、总 summary.json。每轮从相同种子及多候选夹具开始，失败记录也保留；报告不存 cookie、密钥或确认凭据。三次连续通过须查看同一 summary 下所有轮次。mock 备用明确显示 MOCK，不冒充真实模型。

## 备用讲解

- 同名收款人：输入“从活期账户给张三转100元”，选择“尾号3821”；聊天“确认”不会执行，取消操作单后余额不变。
- 单独拒绝冻结：点击“仅拒绝冻结，继续查余额”，显示部分完成和真实余额，卡保持正常。
- 条件变化、请求返回丢失、过期：运行 `scripts/browser-m6.ps1 -Mode mock`，其隔离夹具会分别验证不扣款、读取原回执和失效提示；不能把故障注入脚本用于主数据库。
- live 不可用：说明失败，停止服务后显式以 `dev.ps1 -Mode mock` 启动备用。恢复时先查原任务状态，不能为“重试”而创建新的转账。

## 答辩要点

为什么不用模型算钱？金额是整数分，统计先完整聚合再分页，退款保留来源。

为什么需要页面按钮？聊天文本不构成授权；固定操作单与会话绑定，事务内再验条件和余额，重复请求读同一结果。

模型做了什么？在有限意图和核实参数的约束下返回工具调用；没有任意规划能力，不声称全功能银行代理。

为什么采用 SQLite？可复制、可检查、本地演示成本低；没有证明生产规模、真实银行安全或真人效率提升。
