# FinAgent 前端重设计与验收

改造日期：2026-10-15；最终收尾：2026-10-16。依据用户提供的两张参考图、粘贴提示词及根目录《FinAgent_前端重设计与开发要求.md》。图中样例金额、姓名、时间和进度未写成假数据。本次为 React/Vite 前端渐进改造，不更换框架，不增加依赖，不改 DeepSeek 语义理解、领域交易、权限或后台执行代码。

## 已实施的页面与模块

| 新入口 | 复用的业务与界面 |
|---|---|
| 智能助手 | 浅色首页、自然语言输入、快捷示例；办理态消息、当前固定单、资料表单、回执、余额结果；报告和证据在详情浮层展开 |
| 我的资产 | 账户与近期流水；账单筛选/分类/覆盖/逐笔证据；卡片申请与办理；风险问卷、产品/持仓/订单；订阅黄色查询、提醒与银行代扣；收款人备注 |
| 任务中心 | 服务端最近对话任务、真实步骤和完整目标、暂停/恢复/接管、单独重试读取；预约与 AA；生日办理、专款、订单及送达状态；手工准备操作单 |
| 安全与记录 | 权限说明、全局安全锁提示、当前任务与关联操作标识、按需读取服务端审计、恢复和人工求助 |
| 演示工具 | 实际 Mock/Live 与非秘密模型状态、显式模型探测、独立模拟卡片审批/消费、AA 成员付款、供应商模拟送达、本机坐席；移动端用户切换 |

`App.tsx` 保留用户选择、Expected-User、请求版本/账户序列和失效事件处理。新增 `useAgentWorkspace.ts` 复用原聊天、确认、任务控制及只读回执恢复逻辑；该控制器位于按用户建立的稳定会话层，页面切换不会重建聊天任务。只挂载当前业务页签，不再把全部面板隐藏挂载并轮询。

`AssistantWorkspace.tsx` 负责首页、消息、固定单、实际任务进度与上下文；`AgentPanel.tsx` 保留为兼容导出。`MessageComposer.tsx` 提供 textarea、Enter/Shift+Enter 和中文输入法组合保护。`DetailDialog.tsx` 使用浏览器原生模态 dialog 管理宽报告和窄屏任务详情。`ExecutionRecord.tsx` 按按钮读取已有审计接口，不自动抓取所有记录，不将任务 ID 包装成已实现全链路 trace。

`WorkspaceDrafts.tsx` 仅在内存保留当前用户的聊天资料/手工表单草稿，不写 localStorage；用户切换和会话失效时整个提供者卸载。固定单、认证凭据和授权仍以服务端为准。`TaskDetailsForm.tsx` 和 `OperationPanel.tsx` 复用这个草稿容器。刷新浏览器时未提交表单不保证恢复，已保存任务及回执由后端恢复。

`CardManagement.tsx`、`BankingWorkflows.tsx`、`Birthdays.tsx` 通过显式 demo 属性复用原模拟操作实现；普通业务视图不显示审批、消费、成员付款或模拟送达按钮。原确认、取消、部分失败恢复和订单状态仍保留。`Subscriptions.tsx`、`WealthPanel.tsx`、`SpendingPanel.tsx`、`AnalyticsReport.tsx`、`TransactionEvidence.tsx` 的领域请求和计算口径沿用原实现。

`style.css` 替换旧绿色长页样式，统一浅色/靛蓝、细边线、留白、数值层级、固定内容区输入和断点；`Subscriptions.css`、`Birthdays.css` 调整为同一色板。`Icon.tsx` 使用内联线性 SVG，不依赖网络字体、图标 CDN 或图片服务。优先本机 Noto Sans SC/微软雅黑及系统回退。

## 安全、模型与恢复边界

- 普通聊天依旧原样 POST `/api/tasks` 或原任务 messages；Live 仍先进入后端 DeepSeek 统一语义入口。前端业务链接依据已返回任务类型，未加入自然语言关键词路由或静态示例回复。
- `api.ts` 未改。卡片“核对并继续”仍由确认令牌拦截器先 GET 服务端 SecurityOperation，再进入唯一全局 SecurityGate，最后沿用原 token/confirm 流程。右侧任务栏无第二个交易提交入口。
- 业务卡不按金额猜权限，显示“待核对”；安全窗显示服务器实际黄/红级别、固定条款、金额和跨账户含本笔累计。对象摘要直接取服务器返回的核对摘要。红色仍使用原六位本机模拟验证码，不经过聊天；未新增假人脸/U 盾认证。
- SecurityGate 在页面导航之外，用户切换时取消原确认；增加键盘焦点约束、Escape 取消、关闭后焦点恢复、窄屏全屏布局。核对窗取消不签发令牌。
- 成功由持久回执呈现，不把“受理”“已支付”“送达”合并成一个状态。提交响应丢失时读取原任务；读取失败提供只读恢复，不重发确认。日累计重新分级、幂等、后台安全锁及授权失效均由原后端继续校验。
- 首页快捷示例只填入输入框。没有预选“小林”、自动付款、伪造余额/任务或静默 Mock 降级。首页可用余额仅在所有账户明确提供可用金额时汇总；账户缺字段显示“未提供”。

## 运行与使用

已有本地数据库直接启动，不要重置日常数据。在 `finagent` 目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\dev.ps1 -Mode live
```

打开 <http://127.0.0.1:5173>。选择演示用户进入首页；从顶部或侧栏可辨认实际模式。DeepSeek 连接检查移至“演示工具 → 运行状态”，会产生一次真实请求。使用现有后端本地配置；本轮没有读取或复制真实 `.env`、没有把密钥放入前端或文档。

普通转账在助手卡核对；卡管/理财/订阅/生日/预约与 AA 的业务单在相应页签确认。助手提供对应详情入口。导航不重新提交任务。“助手首页”保留当前任务，继续办理入口可返回；它不会暗中取消、清空任务或签发新授权。

## 当前验收方式

修改前构建及 14 项前端 API 回归通过。修改后执行完整类型检查、生产构建、同一组 API 回归、完整后端回归、原 P0/P1 浏览器回归及新增界面验收。最终结果和运行路径见 `evidence/frontend-redesign-*.json`、`frontend-redesign-backend.xml`。

```powershell
# 前端目录；使用已安装的 Node 24
npm run typecheck
npm run build
npm test

# finagent 目录；均为隔离 TEST-ONLY 数据
.venv\Scripts\python.exe -m pytest backend/tests -q -p no:cacheprovider
.venv\Scripts\python.exe scripts/run-browser-tests.py --suites p0-browser.mjs,p1-browser.mjs,redesign-browser.mjs
.venv\Scripts\python.exe scripts/run-browser-tests.py --suites dialogue-browser.mjs --mode live --api-budget 30
```

新 `redesign-browser.mjs` 检查匿名入口、真实空白态、快捷填入、IME、导航不 POST、草稿/原单保留、改参旧单失效、黄窗取消及焦点约束、丢响应只执行一次、刷新恢复、读取失败只重试读取、手工草稿保留、红窗取消、原业务入口可达、订阅黄色确认、四种视口和任务浮层、切换用户清空及迟到聊天响应隔离。

原浏览器脚本仅适配新导航和“核对并继续”文案，保留余额、权限、独立审批和持久状态断言。P1 原脚本发送后等待空输入按钮启用会白等30秒，已改为等待真实 HTTP 响应。开发中曾因旧选择器、热更新/运行等待和测试定位不匹配产生失败，运行目录保留在 `var/TEST-ONLY/p1-browser-*`；未把失败运行记成通过。
