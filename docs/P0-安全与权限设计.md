# P0 安全与权限设计

版本：2026-10-15。依据为用户提供的赛题原文；赛事名称、官方链接、模拟认证接受程度未提供，不能替组委会确认。

## 权限矩阵

| 操作 | 等级 | 服务端约束 |
|---|---|---|
| 余额、流水、账单、收益/持仓、卡状态、生日状态 | 绿色 | 归属校验，只读工具直接返回后端证据 |
| 本人全部账户当日累计含本笔 ≤1000元的转账 | 黄色 | 固定操作单、页面确认令牌；执行事务重算 |
| 累计含本笔 >1000元的转账 | 红色 | 同上，加独立挑战验证，验证证明一次核销 |
| 条件转账 | 同普通转账 | 原条件仍由领域服务在执行时重算，不由模型降低等级 |
| 一次性预约转账 | 同普通转账 | 授权时分级；到期时按最新累计重新判断；授权等级不足则停止，不自动补强验证 |
| 理财申购（包括100元）、卡片挂失 | 红色 | 按类型固定等级，小额也不能降级 |
| 解冻、线上限制解除、提高交易限额 | 红色 | 本项目保守策略，不宣称赛题指定所有这些细项 |
| 临时冻结、降低交易限额、线上限制、虚拟卡申请 | 黄色 | 固定单和明确确认；申请受理与模拟审批分开 |
| 理财赎回 | 黄色 | 固定产品、账户、份额、费用；领域服务复验锁定期和持仓 |
| 订阅识别/查询 | 黄色 | 专用页面确认，绑定当前用户会话和数据版本，5分钟有效 |
| 提醒、撤销代扣 | 黄色 | 固定单确认；撤销银行代扣不等于取消商户会员 |
| 后台代扣专项授权 | 黄色 | 显示固定账户/商户/金额/月周期，校验当前版本，最多12次、366天有效 |
| 生日预留、修改、采购重试 | 黄色 | 固定预算、商品、供应商、报价和地址；后台须匹配专项契约 |
| AA发起、模拟消费/审批/成员付款/送达 | 明确的模拟操作 | 专用页面按钮、参数校验和幂等；模拟角色按钮不是独立身份认证 |
| 取消草稿、撤销未执行授权、求助 | 锁定期间仍保留 | 不撤销已付款账本，不以撤销操作清除安全锁 |

普通转账原来的单笔5000元、每付款账户每日10000元硬限额仍保留；它们与1000元权限阈值是不同规则。

## 日累计口径

`domain/security.py:daily_total` 按用户跨账户汇总，使用真实安全时间对应的 Asia/Shanghai 自然日。计入已入账的本人互转借方和对外转账借方；本人转入不再重复计数；退款与其他入账不冲减累计。依据实际创建时间计算，演示账单日期与生日测试时钟不能回拨这个安全口径。确认时在 SQLite `BEGIN IMMEDIATE` 写锁内重算，不能用两张旧黄色单绕过升级。

## 独立挑战与模拟边界

本轮采用“演示会话＋本机模拟短信持有因素＋页面确认”。**演示选用户不是真实登录，模拟收件箱不是真实短信服务，本项目不能据此宣称银行级多因子认证或已经获得赛方认可。** 赛方如果要求真实身份认证，必须接入正式登录与独立短信/认证器服务后重新验收。

挑战为随机六位码，180秒有效。HTTP只返回挑战编号，验证码由本机私有收件箱交付，通过 `scripts/auth-code.ps1` 或 `scripts/local-auth.py sms` 查看。验证码使用带随机挑战编号的摘要保存于挑战表，明文仅在本机模拟收件箱，不能开放该目录静态下载。操作绑定用户、会话、资源编号、完整固定条款、数据版本、计划版本、策略版本及到期时间。改参、换单、换用户/会话、过期及已核销的证明不能复用。验证不等待数据库事务；最终核销与资金/卡片变更在同一短事务中提交。

认证接口没有注册到模型工具目录。专用认证值不进入对话；聊天中的显式验证码/密码会被阻止或脱敏。控制台收件箱与录屏必须分开；普通请求日志不打印请求正文。模拟收件箱和 `operator.key` 在 `var/`，源码打包排除整个目录。当前仍依赖本机账户和文件权限保护，尚无硬件密钥库、真实短信或生产身份管理。

## 熔断、后台授权和撤销

错误验证码、伪造确认凭据连续5次触发15分钟锁定；阈值是本项目策略，不是赛题指定数字。计数按用户持久化，换会话、重启不清零；模型/网络异常不计作用户认证攻击。锁定覆盖业务确认和账本借记，因此预约、生日及代扣都不能继续付款。成功撤销不会清除仍有效的锁。

统一 `security_authorizations` 存储对象、条款摘要、策略版本、等级、期限、次数和状态。预约契约1次，绑定目标与执行时点；生日契约受固定预算和商品目录约束，每次只处理未付订单；订阅契约12次/366天且重验每月约定日北京时间09:00、撤销状态及数据版本。旧数据中没有统一专项契约的后台任务会停止，必须重新核对授权。

到期授权失效/等级不足时采用**停止并提示重新办理**策略：预约记录 `failed` 和 `REAUTHORIZATION_REQUIRED`，生日记录 `blocked`，代扣本期记录失败并推进周期；不会自动补令牌或无界重试，也不会自动补扣失败的历史期。用户应依据失败记录重新提交符合当前日期的操作，重新确认/验证。解锁本身不会自动重放这些失败操作。

## 任务控制与人工接管

`task_controls` 是独立持久检查点，不依赖可被后续对话改写的上下文。暂停、待重新验证、接管与终止会阻止新准备/确认及关联后台业务；恢复时核对计划版本。已成功步骤及资金回执保留。用户可在对话面板暂停/恢复/求助。模拟坐席使用本机独立凭据查看接管队列，记录澄清建议、终止或恢复；坐席接口没有业务提交、用户确认或MFA工具。生产坐席登录、组织角色管理不在本轮实现范围。

## 审计与隔离

保留已有 AgentMessage/AgentStep、AuditEvent、账本和领域回执，并新增等级判定、认证成功/失败、授权和任务控制事件。决策依据可从固定单、计划版本、规则、认证绑定与最终回执核对，不保存模型内部思维链。贯穿全业务的统一 trace_id 仍属原清单 P1。

模型仅能产生类型化参数/计划，不执行生成的Python或Shell。工具信封先通过 `python -I -S` 独立受限校验进程：64KiB输入、2秒超时、禁止文件、网络、动态编译/执行及子进程操作。业务事务在受信任领域服务执行；**Python审计钩子不等于对任意恶意代码的完整OS沙箱**。

附带 `compose.yaml` 为mock整应用提供只读根文件系统、唯一数据卷、非root进程、禁止提权、capabilities清空、CPU/内存/PID限制及无外部出口网络。容器配置尚未实跑，不能当作已完成容器验收；Live模型联网不适用这份mock网络配置。容器内验证码可用 `docker compose exec backend python scripts/local-auth.py sms` 查看。
