# 查询回复展示修复

日期：2026-10-17。仅修改后端，保留当前前端、案例数据和 DeepSeek 配置。

复现原话：“近半年内饮食相关的支出”。原任务的本期为 2026-03-24 至 2026-09-24，餐饮消费 5,702.85 元、202 笔、退款 0 元，本期覆盖完整。模型额外选择的对照期有缺口，旧校验把这个缺口套到了整个回答，并将“减少就餐频次”的建议误识别为真实支出下降。校验重试耗尽后，旧兜底直接输出内部错误、重复的事实字段和无关的付款提示。

改进：

- 仅在确实声称真实支出增减时应用缺口限制，允许说明不能比较、以及提出消费习惯建议；继续禁止基于缺口区间计算完整总额或降幅。
- 查询模型默认直接统计用户要求的区间和分类；未要求比较时不额外补上一期。近 N 个月明确为滚动区间，并展示实际统计日期。
- 消费笔数作为独立数值事实提供给模型；引用时检查金额和计数单位，防止出现“金额元笔消费”或“元元”。
- 回答已有核验金额时，仅补充统计区间与数据覆盖情况，不再重复粘贴消费/分类总额。业务失败后的展示改为服务端根据实际结果生成的简明统计摘要，字段路径留在审计记录中。
- 纯查询不再追加“没有自动重做付款”。确实存在已执行业务时才提示查看原回执。

验证：完整后端回归 320 项通过；最终针对查询呈现与动态工具循环的复测见 targeted.xml。真实官方 DeepSeek 在隔离案例副本上复测原问题，以及八月缺口与七月完整餐饮消费比较，两项均 completed。账户、流水、卡片表哈希未变化。

原问题复测结果：2026-03-24 至 2026-09-24，按账本餐饮分类，消费 5,702.85 元、202 笔，退款 0 元，净消费 5,702.85 元，本期覆盖完整。八月缺口案例明确只报告已记录金额，不能确定真实增减。
